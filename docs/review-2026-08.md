# Review 2026-08 (fleet recon)

Verdict up front: **healthiest-documented project in the workspace, with one landmine.** The docs
are dense, honest, and cold-startable. The landmine: main is 19 commits ahead of the public GitHub
remote and those commits contain 18.6 MB of Anthropic's extracted app bundles. The fix already
exists as a commit, stranded in an abandoned worktree.

## 🎯 Philosophy

Make Claude Desktop on Linux actually good: a patched AppImage build carrying a project selector
panel, live usage chip, window-title mirroring (feeds Timekeeper's ActivityWatch), keep-awake
governor, and a `claude-ctl` control surface. Scope is honest and has been trimmed once already
(2026-07-12 cut five dead modules). Still true, still in daily use as the driver app. The one
scope drift worth naming: this started as "a UI patch" and is now also a packaging project,
because upstream pulled the rug (below).

## 📊 Stage

**Working, actively developed.** Last commit 2026-08-25; the working tree has same-day
uncommitted work in progress (`usage.js`/`workspace.js`, issue #46 word-match fix). Not stalled,
the opposite: mid-flight.

## 🧨 The one urgent thing: the unpushed bundles

- `index.js` (13 MB) and `index.chunk-BOXWZA6T.js` (5 MB) are extracted upstream app code,
  committed by accident, still tracked on `main`.
- `origin/main` (public: github.com/behdadmansouri/claude-desktop-tweaks) does **not** have them

  public repo.
- Commit `86d1ddc` ("Untrack the extracted bundle artifacts") already fixes this, with the right
  glob ignore rules, but it lives only in the stale worktree
  `.claude/worktrees/blissful-noether-bd840c` (detached HEAD, clean, branch
  `claude/blissful-noether-bd840c`). It was cut from `3ef6a20` and never merged; main moved on.
- Fix: cherry-pick `86d1ddc` onto main, then `git worktree remove` the stale worktree and delete
  the branch. Do this **before** any push. Since the files were never pushed, no history rewrite
  is needed on the remote; local history keeping them is a size nuisance (pack is 5.4 MB), not a
  leak.

## 🧱 Patch brittleness vs upstream (the assigned question)

Better than it looks, and the failure modes are mostly *loud*, which is the right design:

- `update-ui.sh` locates everything by **content signature**, never filename or version: the main
  bundle by the `FileSystem_$_browseFolder` marker, the Ctrl+Q channel by the per-build
  `$eipc_message$_<uuid>_$_` marker, the frame fix by the `minWidth:600,minHeight:400`
  titleBarStyle signature, the keep-awake governor by the `keepAwakeEnabled` claim body.
- Hard failures (`raise RuntimeError`): missing eipc UUID, non-unique titleBarStyle signature,
  changed keep-awake claim body. These stop the deploy. Good.
- **Soft failures (print a WARNING and continue):** browseFolder handler signature (folder
  one-click silently degrades), titleBarStyle not found (frame left as-is). Run interactively
  you'd see the line; run by the 2-hour `install-autoupdate.sh` systemd timer, nobody reads it.
- Worse for the official build: `cmd_update` in `claude-ctl.sh` re-applies the custom UI with
  `update-ui.sh --official || true`. A hard RuntimeError there is **swallowed**: the timer
  installs a new official version, the patch fails, and the build silently runs unpatched until
  someone notices the panel is gone. This is already known to be a real case, not hypothetical:
  the official 1.26832.0 `mainView.js` lacks the eipc marker (`memory/maintenance.md`), so the
  documented rebase-onto-official plan hits exactly this path.
- Renderer-side (custom-ui.js) is the usual DOM-selector fragility, but the project has learned
  this lesson unusually well: geometry guards, aria-label word matches, the `[cc-dump]` beacon
  for measuring instead of guessing, self-reverting hiders. The 08-22 "DOM stopped carrying
  textContent" incident (#41-45) was absorbed in a day via `labelsOf()`/`bestLabel()`.

Net: one upstream release will not *corrupt* anything, but it can silently strip features on the
official build, and the patched build's base is frozen anyway (next point).

## 🔁 Update path: currently dead, decision pending

`claude-desktop-appimage` left the AUR 2026-08-14. `update-appimage.sh` fails at step 1, the
patched build is frozen at 1.24012.9 while upstream is 1.3xxxx. `maintenance.md` has the honest
option table and the right instinct (rebase the patcher onto the official `.deb`, verified not a
drop-in because of the missing eipc marker). This is the project's real `L` item and TODO.md
already leads with it. The 2-hour autoupdate timer is currently updating only the *unpatched*
official build; for the daily driver it can only re-bake local UI edits.

## 🧊 Reproducible by a cold agent?

Docs: yes, genuinely. `CLAUDE.md` + `memory/maintenance.md` + `memory/issues-fixed.md` would get
a cold agent through a re-patch, a rebase, and the known traps (unquoted heredoc, NUL byte, mv-
not-cp asar swap, don't run claude-quit). Rare quality.

The **skill is the weak link**: `~/.claude/skills/update-claude-desktop/SKILL.md` is frozen at
2026-07-24. A cold agent following it runs `update-appimage.sh`, which fails at `yay -S` because
the package no longer exists; the skill knows nothing about `claude-ctl`, `--official`,
`check-updates.sh`, or the autoupdate timer. It also points at `CLAUDE.md`'s version line, which
is fine, but the whole flow it describes is the dead one. Needs a rewrite once the new base is
picked (or now, to at least say "this path is dead, see maintenance.md").

## 🚀 Leverage

`maintenance.md` plan). Everything else in this project compounds on top of a maintained upstream;
